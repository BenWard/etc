# v2 Dotfiles Manual

This repo now uses Chezmoi as the dotfile manager and `just` as the command runner. Bash remains preferred; Bash and zsh both load managed configuration. The account login shell is not changed.

## Commands

Run these from the repo root:

```sh
just --list
just install
just init
just diff
just apply
just doctor
just update
```

- `just install` installs or updates the Homebrew bundle, initializes Chezmoi with this repo as the source directory, force-applies the managed dotfiles, then runs `doctor`.
- `just init` creates or updates the machine-local `~/.config/chezmoi/chezmoi.toml` from `home/dot_config/chezmoi/chezmoi.example.toml`.
- `just diff` shows the changes Chezmoi would make in `$HOME`.
- `just apply` runs `just init`, then writes the Chezmoi-managed files into `$HOME`.
- `just doctor` checks required binaries, shell startup files, Chezmoi source readability, Atuin local-only config, `bash-completion@2`, and `brew bundle check`.
- `just update` runs `brew update`, applies the bundle, applies dotfiles, then reports mise and Homebrew outdated packages.

Preview before changing files:

```sh
chezmoi --source "$(pwd)" diff
chezmoi --source "$(pwd)" apply --dry-run --verbose
```

## Chezmoi Structure

The repo root contains a `.chezmoiroot` file that points Chezmoi at `home/` as the source-state root. That keeps the source tree separate from repo-only files.

Chezmoi source names map to home-directory targets:

- `home/.chezmoiignore` -> source-state ignore rules, including the real local Chezmoi config
- `home/.chezmoidata.toml` -> shared template data, including `userHostColor`
- `home/.chezmoitemplates/agent-instructions.md` -> shared instructions rendered into Codex and Claude configuration
- `home/.chezmoiremove` -> targets that should be removed, including the legacy `~/.AGENTS.md`
- `home/dot_bashrc` -> `~/.bashrc`
- `home/dot_bash_profile` -> `~/.bash_profile`
- `home/dot_gitconfig` -> `~/.gitconfig`
- `home/dot_claude/CLAUDE.md.tmpl` -> `~/.claude/CLAUDE.md`
- `home/dot_codex/AGENTS.md.tmpl` -> `~/.codex/AGENTS.md`
- `home/dot_config/atuin/config.toml` -> `~/.config/atuin/config.toml`
- `home/dot_config/chezmoi/chezmoi.example.toml` -> `~/.config/chezmoi/chezmoi.example.toml`
- `home/dot_config/mise/config.toml` -> `~/.config/mise/config.toml`
- `home/dot_config/starship.toml.tmpl` -> `~/.config/starship.toml`
- `home/dot_dotfiles_lib/{shell,bash,zsh}/` -> `~/.dotfiles_lib/{shell,bash,zsh}/`
- `home/dot_zshenv`, `home/dot_zprofile`, `home/dot_zshrc` -> corresponding zsh startup files
- `home/dot_dotfiles_lib/git-aliases/executable_*.sh` -> executable helper scripts in `~/.dotfiles_lib/git-aliases/`

Generated files are regular files. The old Rake installer created symlinks; Chezmoi now writes managed file contents unless a future source file explicitly uses Chezmoi symlink attributes.

Repo-only files such as `Brewfile`, `justfile`, `docs/`, and `tools/` live outside the source tree and do not need ignore entries.

The real local Chezmoi config, `~/.config/chezmoi/chezmoi.toml`, is ignored by Chezmoi's target state. Run `just init` to create or update it from `home/dot_config/chezmoi/chezmoi.example.toml` before applying templates. The wizard preserves existing local values and prompts only for new example options that are missing locally.

## Editing Workflow

Edit source files in this repo, then run:

```sh
just diff
just apply
```

If a managed file is edited directly in `$HOME`, bring it back into the source state:

```sh
chezmoi --source "$(pwd)" re-add ~/.bashrc
chezmoi --source "$(pwd)" diff
```

For one-off edits through Chezmoi:

```sh
chezmoi --source "$(pwd)" edit ~/.bashrc
chezmoi --source "$(pwd)" edit --apply ~/.bashrc
```

## Bash and zsh startup

Shared Bash/zsh modules live in `home/dot_dotfiles_lib/shell/`. Shell adapters
live in sibling `bash/` and `zsh/` directories. Shared code targets these two
shells, not arbitrary POSIX `sh`. Executable maintenance scripts remain Bash.

| Entrypoint | Behavior |
| --- | --- |
| `.bash_profile`, `.bashrc` | Shared environment and language helpers; interactive configuration when `$-` contains `i` |
| `.zshenv` | Quiet PATH setup, mise shims, and Homebrew environment defaults for every normal zsh invocation |
| `.zprofile` | Restore PATH precedence after macOS `path_helper`; load existing OrbStack integration |
| `.zshrc` | Shared helpers and native zsh interactive configuration |

Plain non-interactive Bash inherits its environment; no `BASH_ENV` is installed.
The managed zsh entrypoints are installed in `$HOME`. If you choose a custom
`ZDOTDIR`, arrange for equivalent entrypoints there. `zsh -f` intentionally skips
user startup files.

PATH additions do not accumulate on reload. `BREWDIR` can specify a custom
Homebrew prefix; otherwise standard Homebrew locations are detected without
running `brew` on each startup. Mise shims respect `MISE_DATA_DIR`, then
`XDG_DATA_HOME`. Interactive mise activation selects project runtime paths.

Both shells use native mise, fzf, zoxide, Starship, and Atuin integrations.
Starship initializes before Atuin. Bash loads `bash-preexec` before Atuin;
zsh uses its own hooks. Bash retains Readline settings and Bash completion.
Atuin hooks and fzf keybindings require terminal input; piped `bash -ic` or
`zsh -ic` invocations still receive helpers but skip these terminal-dependent
integrations.
Zsh uses `compinit`, native Git/npm completion, case-insensitive matching, and
Emacs keybindings. Insecure completion directories are excluded by `compinit -i`.
Zsh retains native word splitting and unmatched-glob behavior.

`resource` reloads settings and helper definitions in the current process.
Initialization guards prevent duplicate hooks and completion registration;
start a new shell after changing an integration's initialization code.
`resource` preserves session variables and jobs. Existing `TERM` values survive.

Optional untracked overrides load last: `~/.extras.sh`, followed by
`~/.extras.bash` or `~/.extras.zsh`. Shared overrides run for interactive zsh
and whenever Bash loads its managed loader; they do not run from `.zshenv`.
Keep any required non-interactive environment in managed environment modules.

### Applying shell changes

Run `just diff` first. Preserve direct edits before applying. `just diff-shells`
and `just apply-shells` operate only on shell entrypoints and shell libraries,
including removal of superseded managed Bash modules. They leave unrelated
Chezmoi targets, such as local mise tool versions, untouched. Back up preexisting
zsh startup files before first application and migrate their custom settings to
an appropriate override. For this machine, `SKIP_RESOURCE_CHECK=1` belongs in
`~/.extras.sh`.

Validation recipes:

```sh
just test-shells     # isolated behavior tests with stub integrations
just smoke-shells    # real integrations in temporary homes and PTYs
just check-installed-shells  # deployed startup with this machine's environment
just doctor
just dry-run
just check-bundle
```

## Prompt

Starship is configured in `home/dot_config/starship.toml.tmpl` to preserve the old prompt shape:

```text
[HH:MM] ~user@host ~/path#branch ± $
[HH:MM] ~user@host ~/path#branch = $
```

The marker is `±` when the repo has changes and `=` when the repo is clean. The host is omitted only on `Voyager.local`, matching the old prompt behavior. The `user_host` segment color comes from `userHostColor`: the repo default is in `home/.chezmoidata.toml`, and machine-specific overrides belong in the local Chezmoi config at `~/.config/chezmoi/chezmoi.toml` under `[data]`. `home/dot_config/chezmoi/chezmoi.example.toml` is deployed as a copyable example. The value is a semantic Starship color name, not a raw Bash escape sequence.

## History

Atuin is configured in `home/dot_config/atuin/config.toml` with `auto_sync = false`, `search_mode = "daemon-fuzzy"`, and daemon autostart enabled. The Bash integration requires Homebrew `bash-preexec`, which `just install` installs from the Brewfile and the Bash loader sources before `atuin init bash`. No cloud account, sync key, or sync address is configured by this repo.

Both shells record into the same local Atuin database while keeping separate
native history files. Zsh retains 50,000 entries in memory and up to 100,000 on
disk, appends history, and ignores duplicates and commands starting with a space.

`hist` opens Atuin's interactive search. `hist <query>` filters through fzf and
presents the selection for editing: Bash uses a `run:` prompt; zsh places it on
the next command line. Enter executes; cancellation executes nothing. Without
Atuin it falls back to native history, and without fzf it lists Atuin results.

`just migrate-history` imports Bash and zsh history independently. The existing
`.bash-imported` marker is retained. `.zsh-imported` is written only after a
successful import from `${ZDOTDIR:-$HOME}/.zsh_history`; absent or empty zsh
history remains eligible for later import. Markers live in Atuin's XDG data
directory. Importing does not rewrite native history files.

Useful commands:

```sh
atuin search
atuin stats
atuin import bash
```

Run `atuin register`, `atuin login`, or `atuin sync` only if you intentionally want cloud sync later.

## Directory Jumping

`zoxide` provides the `z` command:

```sh
z project
zi project
```

Unlike autojump, zoxide learns from shell integration and ranks paths by frecency. The command feel stays the same for the common `z name` workflow.

## Runtimes With Mise

Use mise for runtime versions:

```sh
mise use -g node@latest php@latest ruby@latest
mise use node@20
mise install
mise current
```

To temporarily pin an old project runtime without restoring old PATH blocks:

```sh
cd /path/to/project
mise use node@16
mise use php@7.4
mise use ruby@2.7
mise install
```

Prefer project-local `.mise.toml` pins for legacy projects and global pins only when a runtime is broadly needed.

## Retained Helpers

These bespoke helpers remain:

- Docker Compose helpers: `dcshell`, `dcrun`, `dcpytest`
- Git helpers: `gitroot`, `git wt`, `git prune-local`, `github`
- Caire helper: `push-to-dev`
- Editor wrappers: `code`, `nova`, `subl`
- Utility helpers: `cdls`, `lsl`, `lsa`, `http`, `sudohttp`, `killport`, `urlencode`, `uuid`, `pycheck`

`hist` now wraps `atuin search --cmd-only --search-mode full-text` and post-filters command text when a query is provided, preserving the old `history | grep` shortcut behavior without surfacing Atuin prompt-hook artifacts. It prints a `running ...` line first so the command being invoked is explicit. If Atuin is unavailable, it falls back to `history | grep`.
